# Data dictionary and source list — figure_revision_phase1_v2

Generated by `scripts/make_data_dictionary.py`. This document describes every delivered table, the array conventions behind the figures, the model and split provenance, and the exact rules used for random sampling, tier rounding and tied distances.

| test samples | 15,307 |

## 2. Parameter column order (identical in every table and figure)

| index | column | unit (Table 1 sampling basis) |
|---|---|---|
| 0 | `mu_n_pvk` | m^2 V^-1 s^-1 |
| 1 | `mu_p_pvk` | m^2 V^-1 s^-1 |
| 2 | `tau_n_pvk` | s |
| 3 | `tau_p_pvk` | s |
| 4 | `Nc_eff_pvk` | m^-3 |
| 5 | `Nv_eff_pvk` | m^-3 |
| 6 | `tau_ETL` | s |
| 7 | `tau_HTL` | s |
| 8 | `rad_c` | cm^3 s^-1 |

The unit basis is the one Table 1's sampling ranges are quoted in (manuscript Methods): mobilities and densities of states in SI units, lifetimes in seconds, and `rad_c` in cm$^3$ s$^{-1}$. This matters only for the absolute value of the shared-scale coordinate $a=\log_{10}g$, because $g$ is a geometric mean; log differences and the log-ratio $r$ are invariant to the unit basis. `source_data/unit_basis_check.csv` shows every observed column range falling inside its Table 1 bound.

## 3. Paired coordinates

For each of the three families (mobility, bulk lifetime, DOS) with parameters $(p_n, p_p)$:

- shared scale $a = (\log_{10}p_n + \log_{10}p_p)/2 = \log_{10}\sqrt{p_n p_p}$

- electron-hole log-ratio $r = \log_{10}(p_n/p_p)$


Column ids: `a_mu`, `r_mu`, `a_tau`, `r_tau`, `a_D`, `r_D`. Signed differences are $c_i - c_j$; absolute differences are `absd_*`; baseline-normalised differences are `absd_*` divided by the median `absd_*` of the random pairs.

## 4. Nearest-neighbour pairing

- **Directed links.** For each of the 15,307 test curves, the nearest other test curve under the metric, self excluded. The primary metric (M1) is the RMSE over the 131-point curve in normalized current coordinates, the paper's metric.

- **Undirected edges.** Each directed link is mapped to the ordered pair `(min(i,j), max(i,j))` and duplicates are removed with `key = lo * N + hi; np.unique(key, return_index=True)`. The representative kept for an edge is the directed link with the smallest source index, so the set is reproducible.

- **Tied distances.** The nearest neighbour is taken with `np.argmin`, which returns the lowest index among tied minima. Ties are therefore resolved deterministically in index order and no tie is broken at random.

- `nearest_neighbour_links.csv` gives, for every test sample, its directed nearest-neighbour index and distance, so the directed-to-undirected step can be audited line by line.

- The archived EXP4 analysis used a different rule, `i < NN(i)`, which keeps a directed link only when it points upward and therefore drops every edge whose only link is the downward one. This round replaces it with the rule above, applied identically to M1-M6 (see `report/TABLE_S10_DRAFT_V2.md`).

## 5. Random-pair baseline

| item | value |
|---|---|
| generator | `np.random.default_rng(42)` |
| draws | 200,000 ordered index pairs, uniform over the test set |
| self-pairs | removed (`i != j`) |
| retained | 199,985 |
| rule | unchanged from the archived analysis: same seed, same size, same removal |

The baseline median used as the normalisation denominator is the median of the absolute coordinate difference over these pairs. The pairs actually drawn are delivered in `source_data/fig3_random_pairs.csv.gz` so the baseline can be re-run without re-drawing.

## 6. Tier and rounding rules

- Tier size: $k = \max(1, \mathrm{round}(M f))$ with $M$ the number of undirected edges and $f$ the tier fraction. For M1 ($M$ = 11,245) the closest-1% tier holds $k$ = 112 pairs.

- Tiers are the $k$ smallest curve distances, sorted with `np.argsort(kind='stable')`, so equal distances keep index order.

- The same rule is used for every metric and every tier in this delivery.

## 7. Row order of the frozen arrays

- Every per-sample table is indexed by the zero-based test index `0 .. 15306`, in the frozen array order. It is **not** a Sample_ID.

- `test_index -> Sample_ID` is taken from `supplementary_validation_v4/T2_control/_data_physical.npz` and is accepted only because `params_phys[idx_test]` and `J_phys[idx_test]` reproduce the frozen `params_test_raw` and `J_test_raw` exactly; the script asserts this on every run. Sample_IDs are quoted only where that mapping is available, and the two figures carry them beside the test indices.
