一、这一轮做了什么
----------------------------------------------------------------
原图是「共享坐标轴」排版：x 轴刻度数字只画在底行，y 轴刻度数字和刻度线
只画在左列。这一轮把缺的刻度全部按各图自己的坐标补回：

  · 第 1、2 行六个直方图：补回各自的 x 轴刻度数字（共 24 个数字）。
    x 轴刻度短线九张图本来就有，原样保留。
  · 第 2、3 列六个直方图：补回各自的 y 轴刻度数字与刻度短线
    （共 28 个数字 + 28 条 3 pt 短线），样式与左列完全一致
    （短线向外 3 pt，数字距轴线 6.5 pt，Arial 12）。
  · 左列三张的 y 轴数字、底行三张的 x 轴数字：原图就有，未改动。

二、刻度值是算出来的，不是看着截图填的
----------------------------------------------------------------
依据：原始绘图脚本 final_figures/scripts/plot_FigS1_eda.py
      + 原始数据 data/JV_database_9D_interface_lifetimes-2.csv
      （N = 102,046 条保留样本，seed 42 的 LHS 之后）
脚本路径原样复现（同样的 3×3 gridspec、每图 60 个 bin、nice_ticks 规则、
matplotlib 自动留白），把九条坐标轴的 view 范围和刻度值从活的坐标轴上读回来。

交叉核对（这是能证明「算的就是这张图」的关键）：
  · 九张图 x 轴刻度短线在图上的位置 vs 算出来的位置，最大偏差 0.0009 pt；
  · 左列三张的 y 轴刻度线与数字，位置最大偏差 0.0010 pt，文字逐个相同；
  · 九张图全部 540 根柱子的柱顶高度 vs「计数 ÷ 纵轴上限」，最大偏差 0.0011 pt。
柱子高度这一条同时锁定了第 2、3 列那六张「原先看不见」的纵轴范围。

四、纵轴为什么不能共用（按您的要求逐图核对过）
----------------------------------------------------------------
九张图的纵轴范围（0 … 上限）分别是：
  mu_n 2500.00 :  tau_n 2444.40 :  tau_p 2500.00
  mu_p 2345.70 :  tau_ETL 2106.30 :  tau_HTL 2163.00 :  r_rad 2151.45
  N_c 3264.45 :  N_v 3289.65
没有任何两张图的「范围 + 刻度」同时相同（刻度组合相同的几组，范围也各不相同），
所以九张全部保留各自的纵轴刻度数字，没有共用、也没有为了统一外观去改任何轴范围。

两点如实说明（都是原图本来的样子，不是这一轮改的）：
  1. 左列三张的纵轴上限正好等于最高的一条刻度（mu_n/tau_p 的 2500），这是
     matplotlib 被显式指定刻度后把 view 拉到刻度上的结果；第 2、3 列那六张
     用的是默认 5% 留白（上限 = 峰值 × 1.05）。两套上限都原样保留。
  2. tau_n 的最高刻度候选值是 2500，但它的纵轴上限是 2444.40，2500 落在框外，
     所以该图纵轴刻度到 2000 为止 —— 没有把轴拉到 2500 去迁就刻度。
