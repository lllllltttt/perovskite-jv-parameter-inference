Why the original LHS Sample_ID is not recoverable locally
---------------------------------------------------------
The database params were written to MAT at ~3 significant figures by the
server MATLAB script (e.g. LHS 4.478262e-06 -> MAT 4.48e-06; 2.925323e22 ->
2.93e22). params_test_raw therefore carries ~3-sig-fig rounding. Matching it
against the full-precision LHS CSV (PSC_LHS_9D_interface_lifetimes_200000_3.csv)
succeeds for only 145/15307 rows at the finest lossless tolerance, and at a
coarser tolerance the match is not unique (LHS log10 spacing ~1e-5 << rounding
~1e-3). => original_sample_id column is left NaN (flagged).

Server-side recovery recipe (optional, if the LHS id is needed):
  On the server, the filtered database CSV JV_database_9D_interface_lifetimes-2.csv
  contains the authoritative Sample_ID column. Join comsol_true_parameters.csv
  to that CSV on the 9 physical columns with a relative tolerance ~1e-3
  (nearest-neighbor; matches will be approximate because of the rounding).
